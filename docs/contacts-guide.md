# Что делает наша часть проекта

Контакт — это человек, с которым работает команда: клиент, партнёр или подрядчик.
Наша часть сервера позволяет добавить его карточку, получить список или одну
карточку, изменить сведения и удалить запись, если она нигде не используется.

## Как проходит запрос

1. Пользователь заполняет форму контакта в интерфейсе.
2. Фронтенд отправляет JSON на `POST /api/v1/contacts`.
3. Обработчик (`handler`) читает запрос.
4. Слой правил (`usecase`) очищает пробелы и проверяет поля.
5. Хранилище (`storage/memory`) проверяет связанные ID и сохраняет карточку.
6. Сервер возвращает 201 и всю карточку, включая выданный ID и даты.

На Python это было бы похоже на маршрут FastAPI, модель входных данных,
проверки и сохранение в словарь. У нас эти обязанности разделены по папкам.

В ТЗ проекта изменение и удаление делаются через POST с `/update` и `/delete`.
Хотя в других API часто используют PUT/PATCH и DELETE, здесь следуем общему
контракту, чтобы фронтенду и остальным участникам не пришлось подстраиваться.

## Что важно понимать при сдаче

- Карточка ответа `Contact` содержит ID и даты, а входная `ContactInput` — только редактируемые поля.
- Имя и хотя бы один способ связи обязательны.
- Если ответственный не передан, сервер ставит пользователя с ID 1.
- Изменение заменяет все редактируемые поля; пропущенные необязательные поля очищаются.
- После перезапуска созданные карточки пропадут: постоянная база данных будет позже.
- Связи с другими сущностями пока моковые; для интеграции они описаны в README.
- Загрузка ветки и открытие PR не означают, что код уже принят в main: для этого нужно ревью команды.

Практические команды запуска и примеры находятся в README и `docs/contacts.http`.
